### 3. Opt-out-Pfad (Prüfpunkt 3) — kritischster Befund

- Template-Links: `https://www.nexifyai.cloud/unsubscribe?email={{email}}` → **HTTP 404** (keine Route; Website ist Vercel, Route lebt unter /api/outreach/unsubscribe).
- Route `route.ts`: verlangte `token`, das kein Template rendert → Abmeldung technisch unmöglich. Fix: Token optional (E-Mail genügt, Token bleibt Hardening). Route antwortet generisch (kein Email-Existenz-Leak), persistiert in OUTREACH_UNSUB_FILE (Env, nicht gesetzt) und gibt Bestätigungsseite zurück.
- **Restrisiko:** Website-Route-Fix liegt als GitLab-MR !1 bereit; Live-Deploy erst nach Auflösung des fremden Merge-Konflikts (site-header.tsx/layout.tsx UU, Stash-Merge) in main + GH-Action deploy-vercel.yml. Bis dahin: Opt-out-Link funktioniert NICHT (404/Token). Mails im heutigen Lauf enthielten den neuen Link (Route erst nach Deploy aktiv) — da Token optional gemacht wird, ist der neue Link nach Deploy sofort funktionsfähig. Empfehlung: Merge sofort auflösen oder Route-Deploy anders vorziehen.

### 5. Interessenabwägung (Prüfpunkt 5)

- Herkunft: Leads via SearXNG/öffentliche Quellen (Unternehmenswebsites, Branchenverzeichnisse) — keine gekauften Listen, keine Scraping-Aggregatoren mit Personenbezug.
- Empfänger: gewerbliche Entscheider (B2B), E-Mail aus öffentlicher Firmenpräsenz.
- Interesse NeXify: Vertrieb eigener Automatisierungsdienstleistungen (Angebotsprozess-KI) — legitimes Direktvertriebsinteresse.
